Theme preference, stored in localStorage

Session banner. The kind of thing you dismiss once per tab and never think about again — and then dismiss again in every fresh container, forever.

The preference is localStorage["fmnfix.theme"]. The class on <html> is only ever a rendering of it, rewritten from storage on every load — so replaying the class alone does nothing here.

Passes when, on a fresh load with the ls entry replayed: sawAtParse === "dark" — the site read our value as if it had always been there. bg is rgb(32, 33, 34) with no light frame in front of it.
Picks the wrong rung when only the class entries were replayed. Measured 2026-08-17: the page still ends up dark, because re-assertion at DOM ready puts the class back after this script wipes it — so the end state cannot tell the two rungs apart. The tells are sawAtParse === null (the site never saw our value), a light flash before DOM ready, and a trace line reading re-asserted at DOM ready … the site had overwritten them. That is the health signal doing its job: it works, but only by fighting, and it will stop working the moment the site moves its overwrite later. Prefer the ls entry here.
The banner is the ss case, the weakest of the four kinds: replaying it manufactures a resumed session that never existed, and it earns its place only on the counterfactual — you would have clicked Dismiss in every fresh tab anyway.
